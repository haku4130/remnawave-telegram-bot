# Переработка бота под Telegram Premium: анимированные эмодзи, цветные кнопки, путь новичка

Дата: 2026-10-16. Статус: дизайн согласован в чате, ждёт ревью спека.

## 1. Зачем

С 2026-10-08 бот принадлежит аккаунту владельца с Telegram Premium, поэтому бот может слать кастомные
(анимированные) эмодзи в текстах (`<tg-emoji>`) и иконки на кнопках (`icon_custom_emoji_id`). Цветные кнопки
(`style`: `primary` / `success` / `danger`, Bot API 9.4) доступны всем ботам, но почти не используются.

Цели, обе равноправные:

1. **Вид.** Бот выглядит современно и дорого: живые эмодзи, цветные кнопки, аккуратные тексты.
2. **Конверсия новичков.** По снимку 2026-10-15 ~39 % зарегистрировавшихся так и не дошли до работающего VPN:
   27 % вообще не взяли подписку (смотрели «Купить» и уходили, пробный не замечали), из пробных подключились
   лишь 32 %. Путь «старт → пробный → подключение» должен стать короче и очевиднее.

Решения владельца:

- Языки: **русский и английский** в одинаковом виде. `ua/zh/fa` остаются как в апстриме.
- Тексты и эмодзи правятся **в коде** (через Claude, коммит → автодеплой), не в админке кабинета.
- Плотность эмодзи — **«акценты»**: 1–2 анимированных эмодзи на сообщение (в заголовке и у ключевой строки),
  иконки на кнопках — почти везде.
- Механизм — **«тема на выходе»** (подход A): минимум правок в файлах апстрима, чтобы синки не конфликтовали.
- Онбординг: язык — автоматически, правила — без отдельного шага, пробный — одной кнопкой с переходом к подключению.
- Всё одним спеком, выкатка этапами.

## 2. Что уже есть (и что мешает)

- `app/utils/rich_notify.py` — уведомления и рассылки rich-сообщением.

  (`AUTOPAY_MENU_TEXT`, `AUTOPAY_ACTION_CHECK_BALANCE`, `INSUFFICIENT_BALANCE`, `TICKET_MESSAGE_INPUT`) и замаскирует
  любые наши тексты. Пустую папку `ensure_locale_templates` снова заполнит полным снимком.
- Прод-настройки онбординга: `LANGUAGE_SELECTION_ENABLED=true`, `AVAILABLE_LANGUAGES=ru,en`, `SKIP_RULES_ACCEPT=false`,
  `SKIP_REFERRAL_CODE=true`, `TRIAL_DURATION_DAYS=3`, `CONNECT_BUTTON_MODE=miniapp_subscription`,
  `ENABLE_LOGO_MODE=true`, `SALES_MODE=tariffs`. Приветствие — запись `welcome_texts` id=1 (активна).
- Успешная оплата (`app/services/payment/common.py:165`) — захардкоженный русский текст, не rich, не локаль.

## 3. Архитектура

### 3.1. Каталог эмодзи — `app/localization/emoji_catalog.py`

Словарь `имя → (custom_emoji_id, запасной_unicode)`, например `rocket → ('5445284980978621387', '🚀')`.

- Только **официальные наборы** Telegram (`RestrictedEmoji` «Animated Emoji», `NewsEmoji`, `FlagsEmoji`,
  `HandEmoji`): пользовательский набор автор может удалить.
- Обратная таблица `запасной_unicode → имя` (для автоиконок кнопок, §3.4). Строится из каталога; если два имени
  делят один unicode, в обратную таблицу идёт помеченное `primary=True`.
- Функции: `tag(name) -> str` (`<tg-emoji emoji-id="ID">🚀</tg-emoji>`), `by_unicode(ch) -> entry | None`.
- Новые ID ищутся ботом через `getCustomEmojiStickers` / `getStickerSet` (только чтение). Для этого в репо
  добавляется `scripts/emoji_lookup.py <эмодзи...>` (аналог `tg_emoji.py` с msk3).

### 3.2. Тексты форка — `app/localization/fork/{ru,en}.json`

- Плоский JSON только с **переписанными** ключами. Файлы апстрима `app/localization/locales/*.json` не трогаем.
- Порядок слияния в `load_locale`: апстрим → **форк** → `LOCALES_PATH` (сервер). Правка — одна новая функция
  `_load_fork_locale` и одна строка в `load_locale`.
- Метка `{e:имя}` заменяется на `tag(имя)` **при загрузке**, до любого `.format()` (иначе `.format()` прочтёт
  `{e:rocket}` как поле `e`). Неизвестное имя — `ValueError` при загрузке и падение теста.
- Новые ключи (которых нет в апстриме) допустимы только с префиксом `FORK_` — это отличает намеренные новые
  ключи от опечаток и от ключей, переименованных апстримом.
- Флаг `PREMIUM_THEME_ENABLED` (по умолчанию `true`): при `false` слой форка не грузится.

### 3.3. Прод: снимок `locales` на msk3

Разово (с явного «да» владельца, с бэкапом в `/root/backups/`): заменить содержимое
`/root/remnawave-bot/locales/{ru,en,ua,zh,fa}.json` на `{}`. Файлы существуют, поэтому `ensure_locale_templates`
их не перезапишет; папка остаётся местом для срочных правок без деплоя. Выполняется на этапе 1 одновременно
с выкаткой (до неё наши тексты всё равно не видны, после — снимок их бы маскировал).

### 3.4. Middleware темы — `app/middlewares/premium_theme.py`

Request-middleware aiogram (`BaseRequestMiddleware`), регистрируется в `app/bot_factory.py` рядом со
`StaleCallbackAnswerMiddleware`. Работает при `PREMIUM_THEME_ENABLED=true`. Для каждого исходящего метода:

1. **Кнопки** (`reply_markup` типа `InlineKeyboardMarkup` или `ReplyKeyboardMarkup`) — для каждой кнопки:
   - подпись начинается с `<tg-emoji emoji-id="X">F</tg-emoji>` → `icon_custom_emoji_id = X`, тег и пробел
     после него из подписи убираются;
   - иначе подпись начинается с unicode-эмодзи из обратной таблицы каталога → иконка из каталога, эмодзи
     и пробел из подписи убираются (**автоиконки**; так обновляются все кнопки бота, включая админку и новые
     кнопки апстрима, без правки текстов);
   - прочие `<tg-emoji>` внутри подписи → запасной unicode;
   - если `icon_custom_emoji_id` уже задан кодом — не трогаем;
   - если `style` не задан кодом — берём из таблицы темы (§3.5).
2. **Алерты** (`AnswerCallbackQuery.text`) и **сообщения без `parse_mode`** (`parse_mode is None` и нет
   глобального HTML по умолчанию) → все `<tg-emoji>` заменяются запасным unicode.
3. **Подстраховка от экранирования**: в тексте/подписи с `parse_mode=HTML` экранированный тег
   (`&lt;tg-emoji emoji-id=&quot;\d+&quot;&gt;…&lt;/tg-emoji&gt;`) восстанавливается в настоящий и пишется
   `warning` в лог с методом и началом текста — такие места чиним точечно.
4. Rich-методы (`sendRichMessage` и т. п.) не трогаем: HTML там допускает `<tg-emoji>`, кнопки внутри полотна
   переносит `rich_buttons.py`. Но клавиатуру `reply_markup` у rich-сообщения обрабатываем, как в п. 1.

Middleware не делает сетевых вызовов и не меняет объекты вызывающего кода (копирует разметку перед правкой).

### 3.5. Тема цветов — `app/utils/button_theme.py`

Таблица правил `(вид совпадения, значение) → style | None`, порядок важен, первое совпадение побеждает:
точное `callback_data`, префикс `callback_data`, тип кнопки (`url`, `web_app`, `copy_text`, …).

Смысл цветов (едино для всех экранов):

| Цвет | Когда | Примеры |
|---|---|---|
| `success` (зелёный) | одно главное действие экрана | `trial_activate`, подключиться (`web_app` подписки, `subscription_connect`), купить/подтвердить оплату, продлить, пополнить |
| `primary` (синий) | второстепенные действия | разделы меню (подписка, баланс), выбор тарифа/периода/способа оплаты |
| `danger` (красный) | отмена и необратимое | отказ, удаление, отключение автоплатежа, отмена тикета |
| нет цвета | навигация | `back_to_menu`, `back_*`, «назад», пагинация |

Явный `style=` в коде всегда побеждает таблицу. Таблица покрывается тестами на конкретных `callback_data`
из `app/keyboards/inline.py`. Существующие умолчания `button_styles_cache.DEFAULT_BUTTON_STYLES` и
`CALLBACK_TO_SECTION` переиспользуются для разделов главного меню, а не дублируются.

### 3.6. Деградация

Если Premium у владельца кончится, Telegram молча заменит кастомные эмодзи запасными — бот продолжит работать.
Если сервер Bot API отвергнет `style`/`icon_custom_emoji_id` (не ожидается, Bot API ≥ 9.4), это видно в логах;
мгновенный откат — `PREMIUM_THEME_ENABLED=false` + перезапуск.

## 4. Визуальный язык

- **Акценты:** анимированный эмодзи в заголовке сообщения и максимум у одной ключевой строки. Списки — без
  эмодзи у каждого пункта.
- Заголовок сообщения — жирный абзац (`<b>`), не `<h3>/<h4>/<h6>` (засечки на мобильном). Касается и
  `rich_menu.py`.
- Тон: коротко, на «вы», без восклицательных знаков в служебных сообщениях; сначала главное, потом детали.
- Кнопки: глагол + объект, 1–3 слова; иконка почти у всех, кроме навигации.
- Английские тексты — того же объёма и смысла, что русские (не дословный перевод).

## 5. Путь новичка

### 5.1. `/start` нового пользователя

- **Язык — автоматически** (новый флаг `LANGUAGE_AUTO_DETECT=true`): `message.from_user.language_code`
  `ru|uk|be|kk` → `ru`, иначе `en` (с учётом `AVAILABLE_LANGUAGES`). Экран выбора языка пропускается;
  кнопка «Язык» в меню остаётся.
- **Правила — без отдельного шага:** `SKIP_RULES_ACCEPT=true` в `.env`; в приветствии строка
  «Нажимая кнопку, вы принимаете правила» со ссылкой `https://t.me/<bot_username>?start=rules`.
  Новый payload `rules` в `cmd_start` показывает текущие правила из БД (тот же текст, что в «Инфо → Правила»),
  с кнопкой «В меню».
- Обязательная подписка на канал, deep links кампаний/рефералов, веб-авторизация — без изменений.

### 5.2. Приветствие (`FORK_WELCOME`)

Текст — нынешняя запись `welcome_texts` id=1, переложенная в локаль форка (ru + en) с эмодзи по правилу акцентов:

> **Привет, {user_name}!** 👋
> Это ZanityVPN — быстрый VPN для телефона, компьютера и ТВ. YouTube без рекламы, звонки в WhatsApp.
> 🎁 Дарим **3 дня бесплатно** — без карты.
> Нажимая кнопку, вы принимаете [правила](t.me/<bot>?start=rules).

(«3 дня» берётся из `TRIAL_DURATION_DAYS`, не хардкод.) Кнопки: зелёная «🎁 Попробовать бесплатно»
(`trial_activate`, сразу активирует пробный), «💎 Тарифы» (`menu_buy`). Если пробный недоступен (уже был) —
приветствие без пробного, зелёная «💎 Выбрать тариф».

При `PREMIUM_THEME_ENABLED=true` новое приветствие используется вместо `welcome_texts`; запись id=1 выключается
(`is_enabled=false`) на этапе 2 с «да» владельца — чтобы админка не показывала неработающую настройку.

### 5.3. Пробный включён (`FORK_TRIAL_READY`)

Заменяет `MAIN_MENU_RICH_TRIAL_ACTIVATED` / экран успеха `activate_trial`:

> 🎉 **Готово! Доступ до {end_date}**
> **Шаг 1.** Нажмите «Подключиться» — откроется инструкция для вашего устройства.
> **Шаг 2.** Установите приложение и нажмите в нём «Добавить подписку».
> Не получается? Напишите нам — поможем за пару минут.

Кнопки: зелёная «🚀 Подключиться» (как сейчас: режим `CONNECT_BUTTON_MODE`, страница подписки), «🛟 Помощь»
(`menu_support`), «В меню».

### 5.4. Главное меню

- Rich-меню: заголовки `<h4>/<h6>` → жирные абзацы; тексты `MAIN_MENU_RICH_*` переписаны в форке.
- Классическое меню (`MAIN_MENU`) — те же тексты, на случай отката rich.
- **Главная (зелёная) кнопка зависит от состояния** (одна на экран):
  - пробный доступен и подписки нет → «🎁 Попробовать бесплатно»;
  - подписка активна → «🚀 Подключиться»;
  - подписка истекает (≤ 3 дней) или истекла → «🔄 Продлить».
- Остальные: «Подписка», «Баланс» — синие; «Друзья» (рефералы), «Поддержка», «Инфо», «Язык» — без цвета.
  Строка-подсказка о реферальной программе в тексте меню (рефералы — лучший канал роста).
- Раскладка задаётся умолчаниями меню в коде (`MENU_LAYOUT_ENABLED` на проде включён, но конфигурации в БД нет).
  Конкретное место правки (умолчания конструктора `app/services/menu_layout/` или `get_main_menu_keyboard`)
  определяется в плане по тому, какая ветка реально работает при `MENU_LAYOUT_ENABLED=true` без конфигурации.

## 6. Охват остальных экранов

Два уровня:

1. **Автоматически, весь бот** (этап 1): автоиконки кнопок (§3.4) + цвета по теме (§3.5). Тексты сообщений
   автоматически **не** меняются (иначе получится насыщенный вариант).
2. **Вручную переписываются тексты сообщений** (ru + en, ключи в `fork/*.json`):
   - **Покупка и оплата:** список тарифов, период, подтверждение, недостаточно средств, успех покупки, продление,
     смена тарифа (`TARIFF_*` из `tariff_purchase.py`), баланс (`BALANCE_INFO`), выбор способа оплаты,
     ввод суммы, **успешная оплата** — захардкоженный текст из `payment/common.py:165` переносится в ключ
     `FORK_PAYMENT_SUCCESS` (правка вызова — одна строка).
   - **Уведомления:** `SUBSCRIPTION_EXPIRING_PAID`, истечение, `TRIAL_ENDING_SOON`, винбэк (день 1 и волны
     скидок), `AUTOPAY_SUCCESS`/`AUTOPAY_FAILED`, `WEBHOOK_USER_NOT_CONNECTED`, `WEBHOOK_SUB_FIRST_CONNECTED`,
     `WEBHOOK_SUB_EXPIRED`, `AUTO_PURCHASE_SUBSCRIPTION_SUCCESS`.
   - **Подписка и подключение:** `SUBSCRIPTION_INFO` и статусы, экраны подключения (`SUBSCRIPTION_CONNECT_*`,
     `SUBSCRIPTION_LINK_STEP*`, `HAPP_DOWNLOAD_PROMPT`).
   - **Рефералы, поддержка, инфо:** `REFERRAL_PROGRAM_TITLE` и основная статистика, `SUPPORT_INFO`,
     `MENU_INFO_HEADER`, основные `TICKET_*` для пользователя.
   - Админские тексты (`ADMIN_*`) — только автоматический уровень.

Точный перечень ключей каждого этапа фиксируется в плане реализации.

## 7. Проверка

**Тесты (pytest, в CI):**

- каталог: ID — цифры, запасной — один эмодзи, обратная таблица без неоднозначностей;
- загрузчик: `{e:имя}` → тег; неизвестное имя — ошибка; каждый ключ `fork/*.json` либо есть в апстриме, либо
  начинается с `FORK_`; набор `{плейсхолдеров}` у ключа форка совпадает с апстримом (иначе `.format()` упадёт
  после синка); при `PREMIUM_THEME_ENABLED=false` форк не грузится;
- middleware: иконка из тега и из unicode, чистая подпись, явные `style`/`icon_custom_emoji_id` не перезаписаны,
  цвет по таблице, алерты и `parse_mode=None` → запасной unicode, восстановление экранированного тега, rich-методы
  не тронуты, исходная разметка вызывающего не мутирует;
- тема: ожидаемый цвет для списка реальных `callback_data`;
- онбординг: автоязык по `language_code`, payload `rules`, выбор главной кнопки меню по состоянию.

**Предпросмотр до мержа:** `scripts/preview_screens.py --to <telegram_id>` собирает ключевые экраны этапа на
фиктивных данных через настоящие тексты, клавиатуры и middleware и шлёт их **одному** адресату (владельцу).
Запуск на msk3 из копии ветки в текущем образе бота (`docker run --rm -v <ветка>:/app --env-file .env …`),
Telegram через `socks5h://`. Каждый запуск на сервере — с «да» владельца.

## 8. Выкатка

Каждый этап — отдельный мерж в `main` (= автодеплой на msk3) после предпросмотра и «да» владельца:

1. **Фундамент:** каталог, загрузчик форка, middleware, тема цветов, автоиконки всех кнопок,
   `PREMIUM_THEME_ENABLED`; одновременно — очистка `locales` на msk3 (§3.3).
2. **Путь новичка и главное меню:** §5; `.env`: `SKIP_RULES_ACCEPT=true`, `LANGUAGE_AUTO_DETECT=true`
   (с бэкапом `.env`); `welcome_texts` id=1 → `is_enabled=false`.
3. **Покупка и оплата.**
4. **Уведомления.**
5. **Подписка/подключение, рефералы, поддержка, инфо.**

**Откат:** `PREMIUM_THEME_ENABLED=false` + перезапуск бота (выключает middleware и слой форка без отката кода);
глубже — revert мержа. Изменения `.env`/БД — с бэкапом.

**Оценка эффекта** (через 2–4 недели после этапа 2, теми же запросами, что снимок 2026-10-15): доля новых без
подписки (была 27 %), доля пробных с подключением (была 32 %).

## 9. Вне рамок

- Редактирование текстов/эмодзи в админке кабинета.
- Языки `ua/zh/fa`.
- Причина провалов подключения на Android (Happ) — отдельное расследование.
- Скидка после пробного периода, метки кампаний, лендинг.
